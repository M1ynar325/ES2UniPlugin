ES2 × SNC 跨服互通企划
版本：草案 v0.2    日期：2026-08-14
适用：ES² 以太物语  ↔  SNC
作者：ES2 侧（后续 SNC 可改、可删）

────────────────────────────────
一、要做成什么样
────────────────────────────────

两件事，可以分开发，但共用同一套后台。

1）互通大厅（指令开箱 UI）
   /link 或 /互通 打开一个箱子界面。
   能看到两边玩家上架的货、价格、卖家头颅。
   点一下购买，物品进自己背包，钱按约定结算。

2）世界里的联动箱（类似 QuickShop 的箱子+牌子）
   玩家在本服放一个箱子，贴牌子。
   牌子绑定「对面服务器、某个世界、另一口箱子」。
   用途二选一（第一版先做 A，B 当第二版）：
     A. 商店箱：这口箱子是商店橱窗，库存来自对面那口箱（或共享库存）。
     B. 管道箱：两边箱子内容同步，像跨服末影箱，但是一对一绑定。

大厅负责「逛、上架、买」。
世界箱子负责「放在车站/市场里给人摸」。

────────────────────────────────
二、明确不做（第一版）
────────────────────────────────

- 不整包复制 NBT（潜影盒、刷物品、OP 书会过来）
- 不实时同步任意物品机、管道、漏斗刷屏
- 不把两边 Vault 经济强行合成一个号（除非两边愿意共用经济库）
- 不支持两边模组对不上的物品（对面没有 Create 就不要卖安山合金）

────────────────────────────────
三、物品怎么传
────────────────────────────────

第一版：只传「物品 ID + 数量」，对面现场生成。
  例：create:andesite_alloy × 64
  适合：安山合金、铁锭、模组材料等无特殊数据的货。

第二版：管理端可读 NBT，生成可勾选的标签表，只同步勾中的键。
  「完全可定制」放在管理/上架端，买家仍只看到货名和数量。
  默认全不勾。整包复制 = 勾全选，第一版禁止。

白名单：两边共同有的物品才允许上架。名单两边插件各存一份，改要同步。

────────────────────────────────
三-B、不合规 / 对面不存在
────────────────────────────────

【联动箱：A 有不合规物品，B 看不看得到？】
  看不到。B 侧只渲染白名单内、且本服能生成的格子。
  不合规的货仍留在 A 的箱子里，不会被删、不会被传到 B。
  B 对应格子显示为空（或跳过，不占对面格）。
  漏斗往联动箱塞违禁物：进 A 箱可以，同步时过滤掉。

【买到/传到对面后发现物品不存在】
  例如白名单漏了、模组没装、ID 对不上，给出来是空气或异常。
  收货方可以「反馈异常」：
    1. 物品从收货方收回（还在背包则扣回；已扔/已用则记纠纷，管理审）
    2. 退回卖家本服仓库 / 原箱子（卖家下次上线或开大厅领取）
    3. 该物品 ID 被标记：暂时禁止再上架、大厅显示「异常」
    4. 同一卖家多次被标记 → 管理看日志，可封上架权限
  钱：未使用则原路退款；已使用由管理裁定。

标记分两级：
  黄  该条交易异常（可退）
  红  该物品 ID 全网暂停同步，等两边确认模组后再开

────────────────────────────────
四、钱怎么结（必须先定）
────────────────────────────────

两边各有一套经济的话，ES2 扣款 ≠ SNC 卖家到账。

三选一，签字前定死：

  方案甲  共享经济
          两边经济插件连同一个 MySQL。最省事，等于一个服的钱。

  方案乙  互通点数
          大厅自己记账。本服余额充值/提现到点数。和生存经济隔离。

  方案丙  公共池
          买家在本服扣款进池，卖家定期结算。能跑，别当正式。

手续费、能不能离线上架、退货谁管，写在第五节。

────────────────────────────────
五、功能细则
────────────────────────────────

【大厅 UI】
- 指令打开 54 格箱子界面，可翻页。
- 每格一件上架：物品图标、数量、单价、卖家名。
- 卖家头颅：用正版 UUID 的玩家头。离线/盗版用默认头或皮肤缓存。
- 上架：手里拿着货，点「上架」格，填单价和数量，货从背包扣到共享库。
- 下架：只能下自己的，货退回本服背包（必须当时在本服）。
- 购买：扣款成功才给货；失败不扣库存。
- 分类可选：材料 / 模组件 / 其它（白名单内）。

【世界联动箱 + 牌子】
- 放置：箱子 + 牌子，第一行约定关键字，例如 [LINK]
  第二行：目标服  ES2 / SNC
  第三行：绑定码（或世界名）
  第四行：价格（商店模式）或留空（管道模式）
- 绑定：两边各放一口，用同一个绑定码配对。管理可用指令代绑。
- 第一版商店模式：买的人右键牌子，从共享库存扣货，钱给卖家。
  库存来源 = 上架到该绑定码的货，或对面那口箱里的白名单物品。
- 破坏箱子/牌子：有权限才能拆，拆了解绑。

【头像】
- GUI 用玩家头颅（SkullMeta + UUID）。
- 大厅列表每页可在边栏放卖家头，点头过滤该卖家。

【权限】
- link.use        打开大厅、上架、购买
- link.chest      放置联动箱
- link.admin      强行下架、解绑、改白名单、看日志

────────────────────────────────
六、技术怎么接
────────────────────────────────

两边各装一个插件，连同一份 MySQL（或 MariaDB）。

  ES2 侧：做进 ES2UniPlugin（本服已有 Vault / 箱 UI / 经济）。
  SNC 侧：单独插件，例如 SNCLink.jar，由 ES2 写好交给 SNC 装。
          功能对齐：大厅指令、上架、购买、联动箱、白名单。
          不塞 ES2 的交通/武器/其它系统。

表（草案，实现时可改名）：
  link_listings     上架：id, seller_uuid, seller_name, server, item_key, amount, price, created
  link_chests       绑定：code, server, world, x,y,z, owner, mode
  link_tx           流水：buyer, seller, item, amount, price, time, status
  link_flags        标记：item_key / seller_uuid, level(黄/红), reason, at
  link_whitelist    允许的 namespaced key

事务：锁这一行库存 → 扣款成功 → 给物品 → 标记完成。
任何一步失败回滚，禁止「钱扣了货没有」或双给。

服务器标识：es2 / snc 写死在配置里，不要靠服名猜。

────────────────────────────────
七、分期
────────────────────────────────

第 0 周  两边确认：经济方案、白名单第一批、谁提供 MySQL、纠纷谁回档。
第 1 周  共享库 + 大厅上架/购买（仅白名单材料）。ES2 进 UniPlugin，SNC 交独立 jar。
第 2 周  卖家头颅、下架、流水、管理强拆。
第 3 周  世界箱子+牌子（商店模式）。
以后     NBT 勾选表、管道箱同步、分类检索。

────────────────────────────────
八、白名单第一批（待两边勾）
────────────────────────────────

原版：铁矿、金锭、钻石、下界合金……（按双方同意加）
Create（须两边都有、大版本接近）：
  create:andesite_alloy    安山合金
  （其它齿轮、传动杆等，SNC 列完再补）

没有的模组、没有的物品：禁止上架，插件直接拒。

────────────────────────────────
九、需要 SNC 配合的
────────────────────────────────

1. 提供或共用一台 MySQL，两边插件能连。
2. 装 SNCLink.jar（Paper/Purpur 1.21.x，与 ES2 同大版本更好）。
3. 确认 Create 等重叠模组的物品 ID。
4. 选定经济方案甲/乙/丙。
5. 出问题能回档或有管理在线对账。

ES2 负责：UniPlugin 里做大厅和箱子、写 SNC 那份独立插件、维护表结构。

────────────────────────────────
十一、一句话
────────────────────────────────

不是把物品「传过去」，是两边插件对着同一本库存账买卖；
大厅用指令开箱 UI，世界里用箱子+牌子当实体店；
第一版只卖两边都有的材料，钱的规则必须先写死。
